# BARE LISS. / SKIN STUDIO

Демонстрационный сайт студии лазерной эпиляции. Next.js 16, React 19, TypeScript, Tailwind 4, Framer Motion. Статический экспорт для GitHub Pages.

## Открыть демонстрацию

Публичный адрес после успешного GitHub Actions deployment: **https://daydayday-ai.github.io/bareliss/**.

Ничего устанавливать не нужно: сайт, PLUCK → LASER, выбор зон и демо-запись работают в браузере посетителя. Контактные данные демо-записи не отправляются в студию и не сохраняются на сервере.

## Публикация GitHub Pages

Workflow `.github/workflows/pages.yml` собирает и публикует `out/` после push в `main`. В Settings → Pages выбран источник **GitHub Actions**. При смене репозитория измените `NEXT_PUBLIC_BASE_PATH` и `NEXT_PUBLIC_SITE_ORIGIN` в workflow.

Сборка Pages использует `/bareliss`; изображения, ссылки, SEO и динамические JS-модули учитывают этот префикс. Локальный `npm run dev` работает без префикса. `.openai/` относится к старой попытке публикации Sites и не отправляется в этот репозиторий.

## Запуск

```sh
npm ci
npm run dev
npm run typecheck
npm run build
```

Build: `out/`. Все шесть маршрутов экспортируются в HTML. Шрифты скачиваются Next/font при сборке и обслуживаются локально. Hero — локальный WebP.

## Что работает

- PLUCK: 25 детерминированных волосков; pointer capture, захват, натяжение и вытягивание; клавиатура Tab + Enter.
- LASER: 64 волоска, пространственное определение волосков в радиусе импульса; прогресс, переходы, пропуск, перезапуск, opt-in Web Audio, необязательная вибрация.
- Динамическая загрузка игры возле секции или при нажатии CTA.
- Зоны, фильтры прайса, FAQ, восемь шагов записи, проверка телефона и даты, modal focus trap через native dialog, Escape и возврат фокуса.
- Адаптивная вёрстка, reduced-motion, SEO metadata, sitemap, robots и BeautySalon JSON-LD без вымышленных контактов.

3. `lib/booking.ts`: заменить `bookingAdapter` серверным адаптером CRM/API. Текущая реализация только возвращает DEMO ID; ничего не отправляет и не резервирует реальный слот. Получать доступность с сервера; сервер должен валидировать запрос, предотвращать двойную запись и защищать CRM-ключи. Добавить юридический текст/согласие согласно процессу студии.
4. `data/faq.ts` и `data/studio.ts`: утвердить процедурный контент у специалиста.
5. `public/hero.webp`: временная сгенерированная фотография ткани. Заменить на согласованные брендовые фото. Брендборд не был приложен, использованы палитра и гарнитуры из ТЗ.
6. `data/results.ts`: добавить настоящие пары фото; готовый компонент BeforeAfter автоматически появится. `data/testimonials.ts`: добавить проверенные отзывы с источником.
7. Демонстрация на GitHub Pages публичная. Настройки записи и цены остаются демо до подключения CRM и подтверждения данных владельцем.

## Проверка

`node tests/qa.mjs` — браузерные проверки Chrome с установленным браузером на Windows и сервером на `127.0.0.1:3000`. Отчёт и снимки в `qa/`. Проверяются drag мышью и касанием, полный game flow, keyboard, skip/restart, запись, фильтры, FAQ, ширины 320–1920, reduced-motion, маршруты и console/page errors.

Цена, доступность и запись явно обозначены на сайте как демонстрационные. Никакие отзывы, рейтинги и результаты процедур не выдуманы.
